# Plan : Retravail design du tooltip et spotlight d'onboarding

## Contexte
L'onboarding existant fonctionne correctement mais a un rendu visuel "cheap" / prototype :
- Spotlight : fond noir trop opaque, halo violet agressif (`drop-shadow-[0_20px_35px_rgba(99,102,241,0.45)]`), stroke fin de 1px peu visible, blur de 1px imperceptible.
- Tooltip : barre de progression de 1px trop fine, hiérarchie visuelle brouillée (trop de badges/pills de tailles différentes), espacements inconsistents, message missing en `text-amber-100` illisible sur fond sombre, manque de transitions douces.

## Design system de référence
- **Couleurs** : `bg-popover`, `border-border`, `text-foreground`, `text-muted-foreground`, `primary` (indigo).
- **Ombres** : `shadow-2xl` pour les popovers/modales, pas de glow violet agressif.
- **Bordures** : `rounded-xl` (16px) ou `rounded-lg` (8px), bordures `border-border` subtiles.
- **Typographie** : `text-sm` pour le corps, `text-xs` pour les méta-données, `font-semibold` pour les titres, tracking serré.
- **Boutons** : `rounded-md`, `transition-colors`, états hover `bg-accent` / `text-foreground`, primary `bg-primary hover:bg-primary/90`.
- **Transitions** : `duration-200` / `duration-300`, `cubic-bezier` doux.
- **Référence** : `NotificationCenterPopover`, `ProjectModal`, toasts `macro-toast` pour la densité et la propreté.

## Étapes

### 1. Amélioration du `TourSpotlightOverlay.tsx`
- **Fond d'overlay** : remplacer `bg-black/55` par `bg-black/40` (ou `bg-background/50`) et `backdrop-blur-[1px]` par `backdrop-blur-sm` pour un effet de profondeur plus doux et professionnel.
- **Contour de l'élément ciblé** :
  - Supprimer le `drop-shadow-[0_20px_35px_rgba(99,102,241,0.45)]` agressif.
  - Remplacer le stroke unique de 1px par un **double stroke** SVG subtil :
    - Un premier `rect` avec `stroke="rgb(var(--primary))"`, `strokeOpacity="0.35"`, `strokeWidth="3"` (aura large et douce).
    - Un deuxième `rect` avec `stroke="rgb(var(--primary))"`, `strokeOpacity="0.9"`, `strokeWidth="1.5"` (contour net).
    - Les deux rects partagent les mêmes `x`, `y`, `width`, `height`, `rx`, `ry`.
  - **Transitions** : ajouter une classe CSS `transition-all duration-300 ease-out` sur les rects SVG pour lisser les changements de position/taille entre les étapes.
- **Rayon** : conserver `SPOTLIGHT_RADIUS = 12` (cohérent avec `rounded-xl`).

### 2. Amélioration de l'`OnboardingGuide.tsx` (tooltip)
- **Apparence globale** :
  - Conserver `bg-popover`, `border-border`, `shadow-2xl`, `rounded-xl`.
  - Ajouter `animate-in fade-in zoom-in-95 duration-200` à l'ouverture/changement d'étape pour un rendu plus fluide (cohérent avec les autres popovers).
- **Barre de progression** :
  - Remplacer `h-1 bg-muted` par `h-1.5 bg-muted/60 rounded-full mx-4 mt-3` (plus visible, mieux intégrée, avec un fill `bg-primary rounded-full`).
- **Header** :
  - Garder l'icône dans son carré `h-9 w-9 rounded-lg border border-primary/25 bg-primary/10 text-primary` (déjà cohérent).
  - Simplifier la méta-ligne : fusionner le badge de section et le numéro d'étape en une seule ligne plus aérée, ou réduire le padding du badge.
  - Titre : `text-base font-semibold text-foreground` (déjà OK).
- **Corps** :
  - Texte principal : `text-sm leading-relaxed text-muted-foreground` (remplacer `leading-6` par `leading-relaxed` pour un rythme plus doux).
  - Liste de points : espacements `space-y-2`, icône `check` légèrement plus visible.
  - **Message fallback** (`usedFallback`) : conserver `bg-primary/10 border-primary/25 text-primary` (déjà cohérent).
  - **Message missing** : corriger `text-amber-100` (illisible sur fond sombre) par `text-amber-400` (ou `text-amber-300`) avec `bg-amber-500/10 border-amber-500/25`.
- **Pills de navigation par section** :
  - Réduire la hauteur (`py-0.5` au lieu de `py-1`) et l'espacement global pour éviter le fouillis.
  - Utiliser `text-[10px]` et `tracking-wide` pour un rendu plus discret.
- **Footer** :
  - Séparation `border-t border-border/60 pt-3` (légèrement plus subtile).
  - Bouton Previous : aligner exactement sur le style des boutons secondary de l'app (`rounded-md border border-border bg-card ...`).
  - Bouton Next/Finish : aligner sur le style primary (`rounded-md bg-primary ...`).
- **Transitions de position** : garder `transition-[top,left] duration-200` mais ajouter `ease-out` pour adoucir le déplacement.
- **Responsive** : conserver `w-[min(23rem,calc(100vw-28px))]`. Vérifier que le padding interne (`p-4`) est suffisant sur mobile (OK avec `calc(100vw-28px)`).

### 3. Accessibilité et polish
- **Accessibilité** : conserver tous les attributs ARIA (`aria-live`, `role="dialog"`, `aria-label`, etc.) et la navigation clavier (Escape, ArrowLeft, ArrowRight).
- **Focus visible** : s'assurer que les boutons du tooltip ont un `focus-visible:ring-2 focus-visible:ring-ring/70` (cohérent avec les autres composants).
- **Spotlight vs tooltip** : s'assurer que le z-index (`z-[13000]`) maintient le tooltip au-dessus du spotlight, et que le spotlight reste `pointer-events-auto` uniquement sur le fond (pas sur le trou).

### 4. Validation
- Exécuter les tests existants (`OnboardingGuide.test.tsx`) pour vérifier qu'aucune logique n'est cassée.
- Vérifier visuellement dans le navigateur (desktop + mobile via DevTools) :
  - Pas de débordement du tooltip.
  - Le spotlight encadre bien l'élément ciblé.
  - Les transitions entre étapes sont fluides.
  - Le contraste des textes est suffisant.
